Этот конспект подготовлен на основе видео Алексея Колесова для передачи сути архитектуры и преимуществ LightRAG другому ассистенту.

### 1. Проблема: что не так с текущей памятью агентов
Автор выделяет 4 критические «боли»:
* **Сброс сессии (Амнезия):** В OpenClaw сессия «умирает» в 4:00 утра, и весь контекст испаряется [[01:11](http://www.youtube.com/watch?v=uboqyhorx2A&t=71)].
* **Раздувание контекста:** Файлы памяти и инструкции загружаются в каждый запрос. Claude Code или OpenClaw могут тратить 30–50 тыс. токенов только на то, чтобы «вспомнить», кто пользователь, еще до начала работы. Это быстро съедает лимиты подписки [[01:53](http://www.youtube.com/watch?v=uboqyhorx2A&t=113)].
* **Изоляция данных:** Память Claude Code не сообщается с OpenClaw. Даже внутри одной системы разные агенты (аналитик, кодер) не делятся знаниями между собой [[02:23](http://www.youtube.com/watch?v=uboqyhorx2A&t=143)].
* **Плоский текст:** Обычные .md файлы не позволяют LLM связывать факты. Если Иван — дизайнер, а встреча с Иваном перенесена, агент без графа не поймет, что перенесена встреча именно по дизайну [[02:54](http://www.youtube.com/watch?v=uboqyhorx2A&t=174)].

### 2. Почему именно LightRAG
Автор аргументирует выбор LightRAG следующими отличиями:
* **От обычного RAG:** Обычный RAG ищет по схожести векторов (плоский поиск), а LightRAG строит полноценный граф знаний с сущностями (нодами) и отношениями (рёбрами) [[04:43](http://www.youtube.com/watch?v=uboqyhorx2A&t=283)].
* **От GraphRAG (Microsoft):** * *Расход токенов:* GraphRAG при поиске отправляет огромные описания кластеров (до 600к токенов). LightRAG намного экономнее [[04:22](http://www.youtube.com/watch?v=uboqyhorx2A&t=262)].
    * *Инкрементальность:* При добавлении данных GraphRAG может перестраивать всю структуру. LightRAG обновляет граф по частям, добавляя только новые связи [[04:59](http://www.youtube.com/watch?v=uboqyhorx2A&t=299)].
* **От Mem0 / Letta:** Mem0 — это скорее память «о пользователе» (визитка), а LightRAG — это память «о проектах» (чертеж здания) [[03:53](http://www.youtube.com/watch?v=uboqyhorx2A&t=233)].
* **От файлов Claude Code (memory/*.md):** Данные LightRAG хранятся **вне контекста**. Агент обращается к ним только по необходимости через инструмент (tool), а не таскает всё в каждом сообщении [[04:43](http://www.youtube.com/watch?v=uboqyhorx2A&t=283)].

### 3. Архитектура решения
* **Компоненты:** Claude Code (локально), OpenClaw (на сервере), LightRAG (как центральный мозг) [[10:27](http://www.youtube.com/watch?v=uboqyhorx2A&t=627)].
* **Связующее звено:** Протокол **MCP (Model Context Protocol)**. LightRAG работает как MCP-сервер, к которому подключаются все агенты [[10:14](http://www.youtube.com/watch?v=uboqyhorx2A&t=614)].
* **Модели:** * *Embedding:* Создает координаты смыслов в графе [[09:03](http://www.youtube.com/watch?v=uboqyhorx2A&t=543)].
    * *LLM для извлечения:* Автор использует **Gemini 1.5 Flash** (через агрегатор AP), так как она дешевая и быстрая для задач «библиотекаря» [[09:52](http://www.youtube.com/watch?v=uboqyhorx2A&t=592)].
* **Хранение:** Граф знаний хранится на сервере в Docker-контейнере, что обеспечивает доступность 24/7 с любого устройства [[20:36](http://www.youtube.com/watch?v=uboqyhorx2A&t=1236)].

### 4. Что изменилось (До / После)
* **Сценарий «Кто я?»:** Без мозга модель говорит, что это первый разговор. С LightRAG — выдает стек, интересы, локацию и текущие проекты из свежей сессии с нулевым контекстом [[11:03](http://www.youtube.com/watch?v=uboqyhorx2A&t=663)].
* **Сценарий «Сложные связи»:** Агент смог ответить, кто делал конкретный дашборд (связал заказчика, исполнителей и компанию), пройдя по цепочке связей в графе, хотя данные были из разных документов [[12:42](http://www.youtube.com/watch?v=uboqyhorx2A&t=762)].
* **Кросс-платформенность:** Факт, надиктованный голосом в Telegram (через OpenClaw), мгновенно стал доступен Claude Code в терминале [[16:02](http://www.youtube.com/watch?v=uboqyhorx2A&t=962)].

### 5. Подводные камни и ограничения
* **Скорость индексации:** Обработка одного документа занимает 30–60 секунд. Загрузка 50 файлов может занять до 30 минут [[21:49](http://www.youtube.com/watch?v=uboqyhorx2A&t=1309)].
* **Качество данных:** «Мусор на входе — мусор в графе». Автор пытался загрузить сырые логи сервера, что привело к появлению бесполезных нод типа «Connection Timeout» [[22:11](http://www.youtube.com/watch?v=uboqyhorx2A&t=1331)].
* **Необходимость чистки:** Иногда агент запоминает лишнее, но это легко правится удалением ноды (функция *Pruning*) прямо в интерфейсе [[22:28](http://www.youtube.com/watch?v=uboqyhorx2A&t=1348)].
* **Что не грузить:** Автор не рекомендует загружать исходный код, логи или дампы баз данных. Лучше фокусироваться на решениях и причинах [[23:42](http://www.youtube.com/watch?v=uboqyhorx2A&t=1422)].

### 6. Practical Setup (установка через Claude Code)
1.  Создать файл `install.md` с пошаговой инструкцией для агента [[17:46](http://www.youtube.com/watch?v=uboqyhorx2A&t=1066)].
2.  Предоставить агенту доступ к серверу (IP, логин, пароль) [[18:14](http://www.youtube.com/watch?v=uboqyhorx2A&t=1094)].
3.  Агент сам проверяет зависимости, ставит Docker и разворачивает LightRAG [[18:50](http://www.youtube.com/watch?v=uboqyhorx2A&t=1130)].
4.  Агент генерирует ключи и конфигурирует MCP-подключения для всех инструментов [[19:04](http://www.youtube.com/watch?v=uboqyhorx2A&t=1144)].
5.  Прописать системные промты (rules), чтобы агенты знали, когда обращаться к памяти, а когда записывать [[14:03](http://www.youtube.com/watch?v=uboqyhorx2A&t=843)].
