# Document Guide v2 — Як створити ідеальний документ для Бази Знань

> Цей гайд описує вимоги до документів перед завантаженням у корпоративну Базу Знань (KB).
> Дотримання вимог забезпечує якісний пошук та точні відповіді AI-асистента.

---

## Чеклист перед завантаженням

Перевірте документ за цими 10 пунктами:

1. **Формат файлу** — `.docx` (Microsoft Word). PDF та `.doc` не підтримуються
2. **Стилі заголовків** — використовуйте Word стилі `Heading 1`, `Heading 2`, `Heading 3` (не просто bold)
3. **Нумерація розділів** — `1. Назва`, `1.1. Підрозділ`, `1.1.1. Пункт`
4. **Титульна сторінка** — стиль `Title` для назви, `Subtitle` для версії; реквізити (№, дата, хто затвердив)
5. **Мінімальний обсяг** — від 300 слів (менше — занадто короткий для індексації)
6. **Наповненість розділів** — кожен розділ має мін. 3 речення змісту
7. **Таблиці** — підпис `Таблиця N. Назва`, рядок-заголовок (шапка), заповненість ≥ 30%
8. **Абревіатури** — розшифровані при першому вживанні: `Інформаційна безпека (ІБ)` або є глосарій
9. **Самодостатність розділів** — уникайте «як зазначено вище», «відповідно до п. 3.2»
10. **Зміст (TOC)** — обов'язковий якщо > 5 розділів (автоматично видаляється при парсингу)

## Критичні помилки

### Bold замість стилів Heading

**Проблема:** Автор виділяє заголовки жирним шрифтом замість Word-стилів.

```
❌ Текст просто виділений bold → парсер не бачить структуру
✅ Застосовано стиль Heading 1/2/3 → парсер розпізнає розділи
```

Парсер має fallback-детекцію bold-заголовків, але вона менш надійна. Валідатор покаже warning `NO_HEADING_STYLES`.

### Ручна нумерація без стилів

**Проблема:** Нумерація `1.`, `1.1` набрана вручну, але стиль параграфа — `Normal`.

Парсер розпізнає числову нумерацію, але без Word-стилів немає ієрархії (H1 vs H2 vs H3).

### Порожні шаблонні таблиці

**Проблема:** Таблиця з заголовками, але без даних (заповненість < 30%).

Такі таблиці лише займають місце в чанках і знижують якість пошуку.

## Як виправити в Word

### Застосувати стилі Heading

1. Виділіть текст заголовка розділу
2. На вкладці **Головна** (Home) оберіть стиль:
   - `Heading 1` (Заголовок 1) — для розділів верхнього рівня: `1. Назва`
   - `Heading 2` (Заголовок 2) — для підрозділів: `1.1. Назва`
   - `Heading 3` (Заголовок 3) — для пунктів: `1.1.1. Назва`
3. Перевірте у **Панелі навігації** (View → Navigation Pane) — заголовки мають з'явитися в дереві

### Додати Title/Subtitle на титульну сторінку

1. Виділіть назву документа на першій сторінці
2. Застосуйте стиль `Title` (Назва)
3. Виділіть версію/підзаголовок → стиль `Subtitle`
4. Ці дані витягуються як метадані документа

### Розшифрувати абревіатури

При першому вживанні:
```
Система управління інформаційною безпекою (СУІБ) забезпечує...
```

Або додайте розділ «Терміни та скорочення» / «Глосарій» на початку документа.

### Зробити розділи самодостатніми

**Головне правило: не пишіть номер пункту в тексті.** При зміні структури документа номери змінюються, а посилання на них — ні. Крім того, при пошуку в Базі Знань контекст між розділами губиться.

**Найкращий варіант — повторити суть одним реченням:**
```
❌ Ризики обробляються відповідно до п. 3.2.
✅ Ризики обробляються за 4 рівнями: прийняти, зменшити, передати, уникнути.
```

**Якщо повтор занадто довгий — посилайтесь за назвою, не за номером:**
```
❌ Див. п. 3.2.1
✅ Див. Політику класифікації інформації
```

Валідатор автоматично виявляє посилання типу «відповідно до п. 3.2», «як зазначено вище», «див. розділ» і показує попередження.

## Що парсер робить автоматично

Парсер видаляє з тексту перед індексацією:

- **Штампи затвердження** — `СТВЕРДЖУЮ`, `ЗАТВЕРДЖЕНО`, `ПОГОДЖЕНО`, `УЗГОДЖЕНО`, `ВВЕДЕНО В ДІЮ`
- **Зміст (TOC)** — рядки з номерами сторінок, стилі `TOC 1-3`, `Зміст 1-3`
- **Рядки підписів** — `Генеральний директор`, `М.П.`, довгі підкреслення
- **Штампи дат** — `«15» грудня 2023 р.`
- **Номери сторінок** — `— 5 —`, `-12-`
- **Протоколи** — `Протокол № 12 від...`

Якщо документ не має Word Heading стилів, парсер намагається розпізнати заголовки за bold-форматуванням (fallback). Це працює для більшості випадків, але стилі — надійніше.
