# Квартальные проекты — план изменений

> Дата: 2026-03-20

## Текущая ситуация

- **Процессы** — основные направления деятельности (11 шт.)
- **Процедуры** — конкретные виды работ внутри процесса (31 активная)
- **KPI** — квартальный, считается по процессам (факт часы / план часы)
- **Квартальный план** — привязан к процессу, содержит цель и ожидаемый результат
- **Месячный план** — привязан к процедуре, содержит плановые часы, сотрудников, компании
- **Задачи** — ежедневные, привязаны к месячному плану, содержат фактические часы

## Проблема

Иногда в рамках процесса возникает **крупный проект** — значимая работа с отдельным бюджетом, сроками и результатом (например, "Аудит завода X"). Сейчас нет возможности:
- Выделить такой проект в квартальном плане
- Отслеживать часы по проекту отдельно от текущей работы
- Сформировать отчётность по проекту

## Решение

Ввести понятие **"Квартальный проект"** — крупная задача в рамках процесса, выделенная в отдельный элемент квартального плана.

### Как это работает

**1. Руководитель создаёт квартальный проект:**
- Выбирает проект из справочника
- Привязывает к процессу (через квартальный план)
- Указывает цель и плановые часы

**2. Квартальный план отображает проекты:**
```
Процесс "Аудит"                    Q2 2026      120ч план
  ├─ Квартальный проект "Аудит завода X"          70ч план
  └─ Текущая работа по процедурам                 50ч план
```

**3. Сотрудник работает как обычно:**
- Создаёт задачи в рамках своего месячного плана (процедуры)
- При создании задачи может **пометить** что работа выполнена в рамках квартального проекта
- Если задача не связана с проектом — она остаётся обычной текущей работой

**4. KPI не меняется:**
- Все часы (и проектные, и текущие) суммируются в процесс
- KPI = факт часы процесса / план часы процесса
- Квартальный проект не создаёт дублирования

**5. Кросс-департаментные проекты:**
- Квартальный проект может охватывать **несколько отделов**
- Сотрудники из разных отделов помечают свои задачи одним проектом
- В отчёте по проекту видно участие каждого отдела (исполнитель — УИБК, ОИТ и т.д.)
- KPI каждого отдела считается отдельно по своим процессам — без пересечений

**6. Отчётность в двух разрезах:**
- **По процессу** — все часы, все процедуры, все сотрудники (как сейчас + KPI)
- **По проекту** — задачи помеченные проектом: часы, сотрудники, компании, отделы-исполнители

### Пример рабочего дня сотрудника

Иванов работает по процедуре "Выездная проверка":

| Задача | Часы | Проект |
|--------|------|--------|
| Проверка серверной ООО "Рога" | 3ч | — |
| Проверка серверной Завода X | 5ч | Аудит завода X |

Обе задачи идут в процедуру "Выездная проверка" → процесс "Аудит" → KPI.
Но 5ч также видны в отчёте по проекту "Аудит завода X".

### Что НЕ меняется

- Месячные планы — создаются и работают как сейчас
- Процедуры — привязка к процессам не меняется
- Ежедневные задачи — процесс создания не меняется, добавляется опциональный выбор проекта
- KPI — формула расчёта не меняется
- Существующие данные — все текущие планы и задачи сохраняются
