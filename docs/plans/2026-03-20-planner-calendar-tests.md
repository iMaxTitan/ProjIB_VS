## 1. CRUD записей

| # | Тест | Как проверить |
|---|------|---------------|
| 1.1 | **Drag процедуры из сайдбара** → создаётся блок с правильным временем/длительностью | Перетащить на ячейку 10:00 Пн |
| 1.2 | **Перетаскивание блока** на другой день/время | Drag существующий блок на Ср 14:00 |

| 1.6 | **Каскад ("пятнашки")** — при перемещении/создании plan-блоки сдвигаются, external — нет | Поставить блок поверх существующего |

## 3. Синхронизация с Outlook

### PULL (↓)

| # | Тест |
|---|------|
| 3.1 | Pull при пустой неделе → внешние события появляются как `external` (серые) |
| 3.2 | Pull без изменений → ничего не обновляется |
| 3.3 | Событие изменено в Outlook → блок становится `returned` (жёлтый ⚠️) |
| 3.4 | Событие удалено в Outlook → `outlook_event_id` очищается, блок становится `distributed` |
| 3.5 | Pull подтягивает **транскрипции** и `has_transcript` |

### PUSH (↑)

| # | Тест |
|---|------|
| 3.6 | Push новых plan-блоков → в Outlook создаются события с категорией "CS Platform" |
| 3.7 | Push modified-блоков (`needs_push`) → обновляется время/subject в Outlook |
| 3.8 | Удаление synced-блока → событие удаляется из Outlook |
| 3.9 | Push > 20 записей → batch разбивается корректно |

### Конфликты

| # | Тест |
|---|------|
| 3.10 | `returned`-блок: drag/resize → `outlook_modified` сбрасывается, `needs_push` ставится |
