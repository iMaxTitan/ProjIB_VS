# Wishlist: Модуль Планирования

> Дата: 2026-03-08
> Статус: обсуждение завершено, готово к реализации

## Контекст

Модуль планирования — самый сложный модуль CS Platform. Текущая реализация работает, но есть две ключевые проблемы:

1. Сотрудникам сложно вносить задачи — нужно навигировать по иерархии планов
2. Расхождение данных в отчётах — аналитика и детальные отчёты считают распределение по-разному

Сейчас сотрудники работают в Excel. Цель — сделать внесение задач в платформу **проще**, чем в Excel.

---

## W-01: Draft → Assign — задачи-черновики с AI-привязкой

### Проблема

Сотрудник, чтобы добавить задачу, должен: Планы → год → квартал → месяц → план → «Добавить задачу». Слишком много шагов. Сотрудник не понимает, к какой процедуре отнести свою работу.

### Решение: двухэтапный флоу

**Шаг 1: Накидать** — максимально просто, из любого источника.
Сохраняется черновик: описание + часы + дата (опц.). Без процедуры, без компаний.

**Шаг 2: Разобрать** — AI-помощник привязывает черновик к плану.
Сотрудник подтверждает или правит предложение AI.

### Точки входа (Шаг 1)

| Источник | Как работает |
|----------|-------------|
| **Бот** (Telegram/Teams) | Одно сообщение: «аудит сервера 2ч» → regex парсит часы/дату, остальное = описание. Без визарда. |
| **Календарь Outlook** | Совещание закончилось → тема = описание, длительность = часы, дата = дата встречи. Всё уже структурировано. |
| **Кабинет** | Быстрая строка ввода в секции «Мои задачи» |

### Интерфейс кабинета (Шаг 2)

Секция **«Мої задачі»** заменяет текущий read-only `CabinetDeadlines`:

```
┌─────────────────────────────────────────┐
│  Мої задачі                     [+ ▾]  │
├─────────────────────────────────────────┤
│  ⚠ Неразобранные (3)    [🤖 Разобрать] │
│                                         │
│  09.03  аудит сервера прод       2ч     │
│  09.03  совещание по КЕДО        1.5ч   │
│  08.03  обновл. документації     3ч     │
├─────────────────────────────────────────┤
│  Последние задачи                       │
│                                         │
│  09.03  настр. фаервол  Упр.вразл  2ч  │
│  08.03  ревью NDA       Догов.заб   1ч  │
└─────────────────────────────────────────┘
```

**Два блока:**
- Сверху — черновики (amber фон, без процедуры). Видны только если есть.
- Снизу — привязанные задачи (с названием процедуры).

**Кнопка [+ ▾]** — быстрый ввод: строка «описание + часы» прямо в кабинете.

**После нажатия [🤖 Разобрать]** — один вызов AI, пакетный разбор:

```
┌─────────────────────────────────────────┐
│  ⚠ Неразобранные (3)                   │
├─────────────────────────────────────────┤
│  ✓ аудит сервера прод        2ч  09.03 │
│    → Упр. вразливостями мережі         │
│                                         │
│  ✓ совещание по КЕДО         1.5ч 09.03│
│    → Метод. супровіду взаємодії         │
│                                         │
│  ⚠ обновл. документації      3ч  08.03 │
│    → ???  [▾ Выбрать процедуру]         │
├─────────────────────────────────────────┤
│  [✓ Принять 2/3]  [⚠ 1 без процедуры] │
└─────────────────────────────────────────┘
```

- AI уверен → ✓ + название процедуры. Клик — можно сменить.
- AI не уверен → ⚠ + dropdown для ручного выбора.
- «Принять N/M» — привязывает уверенные. Остальные ждут ручного выбора.

**Привязка:** UPDATE `monthly_plan_id`, `distribution_type` + INSERT `daily_task_companies`

### Хранение

Черновики — в той же таблице `daily_tasks` с `monthly_plan_id = NULL`:
- Назначение = один UPDATE (не копирование данных)
- View `v_plan_user_company_hours` делает INNER JOIN → черновики не попадают в отчёты
- `monthly_plan_id` уже nullable

### Парсинг

| Данные | Метод | Когда |
|--------|-------|-------|
| Часы, дата | Regex | Сразу при вводе (бот/календарь) |
| Процедура, компании | AI | При разборе черновиков в кабинете |

### Что не меняется

- Head создаёт планы как раньше
- Существующий путь через планы остаётся (AddTaskModal)
- Бот-визард остаётся как альтернатива (для тех, кто хочет сразу привязать к плану)

### Фазы реализации

| Фаза | Что | Сложность |
|------|-----|-----------|
| **1** | Бот: простой ввод «описание часы» → черновик | Низкая |
| **2** | Кабинет: секция черновиков + ручная привязка (dropdown процедур) | Средняя |
| **3** | AI-помощник: автоподбор процедуры | Средняя |
| **4** | Календарь Outlook: автосоздание черновиков из совещаний | Средняя |

### Баг-фикс (сопутствующий)

Текущий бот-визард не сохраняет `daily_task_companies` — задачи из бота выпадают из view распределения. Починить: после insert → скопировать компании из `monthly_plan_companies`.

## W-02: Единый источник правды для распределения часов — ВЫПОЛНЕНО

> Выполнено: 2026-03-08

### Что было

View `v_plan_user_company_hours` в БД уже была обновлена ранее — использует `daily_task_companies` + `daily_tasks.distribution_type`. Файл миграции был устаревший, но живая view корректная.

### Что сделано

1. **Очистка тестовых данных** — удалены `daily_task_companies` для задач 2024-2025 (тестовый импорт)
2. **Backfill** — для 41 задачи 2026 года (Фев + Мар), у которых не было `daily_task_companies`, скопированы компании из `monthly_plan_companies`
3. **Результат**: 100% задач 2026 (у которых план имеет компании) покрыты в `daily_task_companies`

### Итоговое состояние

| Метрика | До | После |
|---------|-----|-------|
| View rows | 496 | 545 |
| 2026 задачи с компаниями | 655/701 | 696/701 |
| Backfill-кандидаты | 41 | 0 |

5 задач января без компаний — их планы не имеют `monthly_plan_companies` (корректно).
