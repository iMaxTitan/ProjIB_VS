# Кабинет сотрудника — Design Document

> **Дата:** 2026-03-04
> **Статус:** MVP спланирован, ожидает реализации
> **Цель:** Дать employee полноценное рабочее пространство с витриной и инструментами

## Проблема

Employee видит только 2 секции (Активність + Плани). Нет доступа к своему KPI, загрузке, трендам. Настройки бота спрятаны в дропдауне хедера. Планирование отпусков — ручное, через руководителя.

## Решение

Новая секция **"Кабінет"** в навигации. Доступна всем ролям, но в первую очередь для employee.

## Структура кабинета (полная версия)

### Блок 1: "Моя сводка" — персональный дашборд

| Элемент | Описание | Источник данных |
|---------|----------|-----------------|
| Часы за месяц | План / факт / % (прогресс-бар) | `daily_tasks` → агрегация |
| Задачи | Всего / выполнено / просрочено (цветовая индикация) | `daily_tasks` |
| KPI | Тренд "было → стало", не голая цифра. Подсказки как улучшить | `lib/ops/kpi/` |
| Мой статус | На работе / отпуск / больничный / командировка | `planned_absences` (новая) |
| Ближайшие дедлайны | 5-7 задач, просроченные красным наверху. Клик → Плани | `daily_tasks` |

**Важно:** KPI без контекста демотивирует. Показывать тренд + факторы влияния.

### Блок 2: "Мои инструменты" — self-service

#### Планирование отпуска / отсутствий
- Календарная сетка — сотрудник отмечает периоды: отпуск (В) / больничный (Л) / командировка (К)
- Утверждение по иерархии: сотрудников утверждает head, head-ов утверждает chief
- При создании табеля → утверждённые периоды автоматически заполняют ячейки нужными кодами
- **Новая таблица:** `planned_absences` (user_id, date_from, date_to, type, status, approved_by)

#### Совещания → задачи
- Подтянуть из Graph-календаря свои совещания
- Одним кликом создать задачу из совещания
- **Требует детальной проработки** — отдельный дизайн-документ

#### Настройки бота и уведомлений
- Перенос из хедера: привязка Telegram/Teams, выбор канала
- Добавить: выбор типов уведомлений (новые задачи, дедлайны, напоминания)
- Расписание тишины: "не беспокоить с 19:00 до 09:00"

### Блок 3: "Моя аналитика"

| Элемент | Описание | Источник |
|---------|----------|----------|
| График загрузки | По неделям за 3 месяца (часы план/факт) | `daily_tasks` |
| Тренд KPI | Кривая помесячно | `lib/ops/kpi/` |
| Распределение по компаниям | На какие компании уходит больше всего времени | `daily_task_companies` |

**Fallback:** Если данных < 2 месяцев → "Недостаточно данных для аналитики"

### Профиль
- Просмотр: фото, должность, ставка (work_rate с пояснением), контакты
- Только просмотр — редактирование через chief

## MVP (Phase 1)

Минимальная версия для получения обратной связи от сотрудников.

### Что входит в MVP:

1. **Новая секция "Кабінет"** в навигации (для всех ролей)
2. **Карточки-метрики:** часы, задачи, KPI (тренд)
3. **Ближайшие дедлайны** (список задач)
4. **Мой профиль** (просмотр)
5. **Настройки бота** (перенос из хедера)

### Что НЕ входит в MVP (техдолг → Phase 2+):

| Фича | Причина отложить | Приоритет |
|------|------------------|-----------|
| Планирование отпуска | Новая таблица `planned_absences` + UI + утверждение + связка с табелем | Phase 2 |
| Совещания → задачи | Требует отдельного дизайна, интеграция с Graph-календарём | Phase 2 |
| Автоподстановка отпусков в табель | Зависит от планирования отпуска | Phase 3 |
| Расписание тишины | Новая колонка + логика в `send.ts` | Phase 2 |
| Выбор типов уведомлений | Расширение настроек бота | Phase 2 |
| Аналитика (графики) | Чистый фронтенд, но объём. После MVP | Phase 2 |
| Мой статус (отпуск/больничный) | Зависит от `planned_absences` | Phase 2 |

## Навигация

```
Employee: Активність | Плани | Кабінет (NEW)
Head:     Активність | Плани | Звіти | Зведена | KPI | Довідники | Кабінет (NEW)
Chief:    Активність | Плани | Звіти | Зведена | KPI | Довідники | Бот | База знань | Кабінет (NEW)
```

## Самокритика

### Сильные стороны
- Закрывает реальную боль: employee сейчас слепой (не видит KPI, загрузку, тренды)
- MVP быстрый — данные есть, нужен фронтенд + 1 API-роут
- Планирование отпуска (Phase 2) снижает нагрузку на руководителя
- Совещания→задачи — уникальный инструмент

### Риски
- **KPI без контекста опасен** — mitigation: тренд + подсказки
- **Аналитика на малых данных пуста** — mitigation: fallback "недостаточно данных"
- **Планирование отпуска без автоподстановки** — в Phase 2 это просто ещё один календарь. Ценность только с Phase 3
- **Расписание тишины** — приятная мелочь, могут не настроить

### Порядок реализации
1. **MVP** — сводка + профиль + настройки бота → обратная связь
2. **Phase 2** — аналитика + планирование отпуска + совещания→задачи
3. **Phase 3** — автоподстановка в табель + расписание тишины
