# KB Gap Analysis — Процес роботи з неотриманими відповідями

## Мета

Систематичний аналіз запитів користувачів, на які база знань не змогла відповісти (ai_refused, low score, no_answer). Результат — створення FAQ-документів, що закривають прогалини, використовуючи найкращі практики ІБ (NIST, ISO 27001, CISA) там, де ПІБ Компанії не містить прямої відповіді.

## Процес

1. **Збір** — SQL-запит до `kb_query_log` з фільтрами: `ai_refused = true`, `top_score < 0.5`, `chunks_found = 0`
2. **Фільтрація** — прибрати сміття (неповні запити, тести, нерелевантні)
3. **Групування** — об'єднати дублі в теми
4. **Аналіз** — для кожної теми:
   - Перевірити, чи є відповідь у існуючих документах БЗ (можливо RAG не знайшов)
   - Якщо немає — знайти best practices (NIST, ISO 27001, CISA, OWASP)
   - Перевірити, що best practice не суперечить ПІБ Компанії
5. **Документ** — сформувати FAQ і завантажити в БЗ
6. **Верифікація** — повторити запити через RAG, переконатися що відповідь знайдена

## SQL-запит для збору

```sql
SELECT query_original, top_score, rerank_top_score, chunks_found, ai_refused,
       LEFT(answer_text, 100) as answer_preview, created_at::date as dt, source
FROM kb_query_log
WHERE ai_refused = true OR top_score < 0.5 OR chunks_found = 0
ORDER BY created_at DESC
LIMIT 100;
```

## Реєстр прогалин

### Статуси
- `open` — прогалина не закрита
- `faq` — закрита FAQ-документом
- `existing` — відповідь є в БЗ, потрібно покращити RAG/чанкінг
- `out_of_scope` — тема за межами БЗ (HR, бухгалтерія тощо)
- `wontfix` — сміття, неповні запити
