name: Архитектура планов — процесс → квартал → месяц
description: process → quarterly_plan (1 процесс × 1 квартал) → monthly_plans (процедуры/инициативы процесса по месяцам). Процесс = основа → KPI.
type: reference
---

## Архитектурное правило

**Процесс** — жёсткий справочник, основа всех планов.

### Иерархия

```
process (справочник)
  │
  quarterly_plan (1 процесс × 1 квартал = 1 план)
  │   process_id, goal, expected_result, status
  │   Контейнер с глобальными целями процесса на 3 месяца
  │
  ├── monthly_plan (procedure_id) — процедура процесса в конкретном месяце
  ├── monthly_plan (initiative_id) — инициатива процесса в конкретном месяце
  └── ...
```

### monthly_plan

Одна строка = план на **одну процедуру ИЛИ одну инициативу** в рамках месяца.

- `quarterly_id` FK → quarterly_plans — **обязательная связь**, через неё определяется процесс
- `procedure_id` (nullable) — процедура жёстко привязана к одному процессу
- `initiative_id` (nullable) — инициатива может быть в разных процессах
- Связанные данные: assignees, companies, tasks — в отдельных таблицах

### Ключевые правила

- Процесс НЕ хранится в monthly_plan — наследуется через `quarterly_id → quarterly_plan.process_id`
- 1 quarterly_plan = 1 процесс × 1 квартал
- KPI считается по процессам → все планы привязаны к процессу через эту цепочку
- Процедура ∈ ровно 1 процесс. Инициатива может быть в разных процессах (M:N через plan_initiatives)

### Constraints (в БД с 2026-04-03)

- **XOR:** `procedure_id` и `initiative_id` взаимоисключающие — одно из двух, не оба сразу
- **Unique:** не может повторяться комбинация (year, month, procedure_id) или (year, month, initiative_id, quarterly_id) — один план на процедуру/инициативу в месяце процесса

## Статуси планів

Єдиний набір статусів для всіх рівнів: `none` → `pending` → `active` → `done`

## Переходи статусів

```
none ──[Створити/Копіювати]──► pending
pending ──[Затвердити]──► active
pending ──[Видалити]──► none (план видаляється)
active ──[Виконано]──► done
active ──[Повернути]──► pending
done ──[Повернути]──► active
```

## Хто може що

| Дія | chief | head | analyst/employee |
|-----|-------|------|-----------------|
| Створити план | ✓ | ✓ | ✗ |
| Копіювати план | ✓ | ✓ | ✗ |
| Затвердити (pending→active) | ✓ | ✓ | ✗ |
| Виконано (active→done) | ✓ | ✓ | ✗ |
| Повернути (active→pending) | ✓ | ✗ | ✗ |
| Повернути (done→active) | ✓ | ✗ | ✗ |
| Видалити план (pending) | ✓ | ✗ | ✗ |

**Правило:** `canEdit` = chief/head (PLAN_EDITORS), повернення/видалення = тільки chief.

## Action bar по статусу (низ деталей плану)

| Статус | Фон | Текст | Кнопки |
|--------|-----|-------|--------|
| none | slate 8% | "Немає плану" | Створити (indigo), З {попер. місяць} (slate) |
| pending | amber 8% | "Очікує затвердження" | Затвердити (green), Видалити (red, chief, з confirm) |
| active | indigo 6% | "В роботі" | Виконано (green), Повернути (slate, chief) |
| done | emerald 6% | "Виконано" | Повернути (slate, chief) |

## Редагування прив'язок (тільки pending)

При `pending` доступне редагування: компанії, проєкти, документи, співробітники.
При зміні статусу на `active` — редагування блокується.

## Ініціативи — окремі правила

Ініціативи належать квартальному плану, не місячному.
Редагуються при будь-якому місячному/квартальному виді якщо `canEdit` (chief/head).
Не залежать від статусу місячного плану.

**Why:** Ініціативи — стратегічний рівень (квартал), їх потрібно оновлювати навіть коли місячні плани вже active/done.

---
name: Plans V2 architecture — plans are primary, processes are static
description: Архитектурное правило Plans V2 — планы первичная сущность, процессы/процедуры — справочник
type: project
---

## Иерархия сущностей

**Статика (справочник):**
- Процессы → Процедуры → Шаблоны задач (routine, циклическая работа)
- Инициативы (change, аномальная/проектная работа)

**Динамика (планы):**
- Годовой план → построен на основе процесса
- Квартальный план → построен на основе процесса
- Месячный план → построен на основе процедуры ИЛИ инициативы
- Задачи → привязаны к месячному плану

## Ключевое правило

Планы — первичная сущность. Процессы/процедуры/инициативы — справочник для:
- Фильтрации и группировки планов
- Аналитики (KPI по процессу = сумма всех планов процедур + инициатив)
- Как паттерн/шаблон при создании планов

## Навигация UI (Plans V2)

- **Левая панель** — СТАТИКА: дерево процессов → процедуры (не меняется, справочник)
- **Центральная панель** — ДИНАМИКА: планы, зависят от выбранного периода (год/квартал/месяц)
- **Правая панель** — ДИНАМИКА: исполнители, задачи

## Месячный план

`monthly_plans` — единая таблица. Каждый план построен на основе:
- `procedure_id` — routine-контур
- `initiative_id` — change-контур

Одна и та же детальная панель для обоих типов планов. Показывает: задачи, часы, ассайны, компании, проекты.

## Инициативы

- `initiatives` — справочник (title, description, source: planned/unplanned, is_active)
- `plan_initiatives` — M:N связь с планами (annual/quarterly/monthly)
- На месячном уровне инициатива создаёт `monthly_plan` с `initiative_id`
- Инициативы добавляются только через отчёт по процессу (месяц + процесс)
- В общем списке планов месяца — показываются только если есть monthly plan

**Why:** Код строился вокруг процедур (ProcedureNode, ProcedureDetailPanel), а должен строиться вокруг планов. Файлы нужно переименовать для ясности.

**How to apply:** Думать в терминах планов. "Открыть" = детали monthly_plan. Процедура/инициатива = "на основе чего" создан план.

## Plans V2 — правила редагування

Редагування доступне ТІЛЬКИ коли план у статусі `pending`. Кнопки редагування в шапці прибрані — editing auto-enabled by status.

### Матриця фільтр × сайдбар

| Фільтр | Сайдбар | Центральна панель | Можливість |
|--------|---------|-------------------|------------|
| Рік | — | AnnualListView (список процесів) | Створення/затвердження планів |
| Рік | Процес | ProcessDetailView (річний план) | Бюджет: CRUD статей (при pending) |
| Рік | Процедура | ✗ не можна обрати | — |
| Квартал | — | QuarterlyListView (список процесів) | Створення/затвердження планів |
| Квартал | Процес | ProcessDetailView (квартальний план) | Замітки, ініціативи (при pending) |
| Квартал | Процедура | ✗ не можна обрати | — |
| Місяць | — | MonthlyPlansListView (список процедур) | Створення/затвердження планів |
| Місяць | Процес | ProcessDetailView ("Звіт по процесу") | Read-only, без редагування |
| Місяць | Процедура | ProcedureView (місячний план) | Повне редагування (при pending) |

### Місячний план процедури — що редагується (при `pending`)

**Середня панель (ProcedureView):**
- Компанії — додавати / видаляти
- Ініціативи — додавати / видаляти
- Проєкти — додавати / видаляти
- Документи БЗ — додавати / видаляти
- Опис місячного плану — редагувати
- Шаблони задач — read-only (авто по процедурі)

**Права панель (EmployeeTasksPanel):**
- Співробітники — додавати / видаляти
- **Тільки з відділу**, до якого прив'язаний процес цієї процедури

### Зміна фільтра — скидання вибору
- Зняття місяця → скидання процедури (процес залишається)
- Зміна кварталу → скидання місяця + процедури
- Зміна року → скидання всього

# Дизайн-предпочтения пользователя

> Задокументировано на основе итеративной работы над `demo-plans-redesign.html` (март 2026)

## Стиль визуала
- **Glassmorphism** — предпочитает: полупрозрачные фоны, backdrop-filter blur, многослойные тени
- **Palette:** только `slate-*`, никогда `gray-*`
- **3D inset** на секциях-карточках (контент-блоки): `inset box-shadow` создаёт ощущение вдавленности
- Стеклянные карточки с `gap` между ними — НЕ список с dividers

## Интерактивные элементы
- **Кнопки без фона по умолчанию** — иконки-кнопки должны быть "голыми" (без background, без border). Фраза: *"вообще без фона как те иконки которые есть"*
- **Цвет несёт смысл, не фон** — не красить фон кнопки, только окрашивать саму иконку (stroke SVG). Фраза: *"не надо было фон менять просто сами иконки цвет"*
- **Семантические цвета для опасных действий**: Delete confirm → красная ✓ + зелёный ✗ (инверсия = сигнал опасности). Edit/Copy → зелёная ✓ + красный ✗

## Переключатели статусов
- **Segmented pill control** — не dropdown, не одиночный badge, а все статусы в ряд в одном контейнере
- **Реальные имена статусов** — не названия групп. Фраза: *"только названия реальных статусов а не названия груп статусов"*
- **Линейная прогрессия** — запрещён возврат назад И пропуск вперёд более чем на 1 шаг. Только текущий и следующий доступны.

## UX паттерны
- **Confirm mode в header** — при выборе опасного действия (удалить/редактировать) интерфейс переключается: заголовок меняет иконки на ✓/✗. НЕ диалог, НЕ inline confirm в дропдауне. Фраза: *"нет не так выбрал а в хедере иконки меняются"*
- **Контекстное скрытие** — в режиме подтверждения скрывать нерелевантные кнопки (плюсик и др.)
- **Кнопка + уровня** — в годовом плане → добавить квартал, в квартальном → добавить месяц, в месячном → добавить задачу

## Стиль работы с макетом
- Итеративный процесс: быстрый скриншот → короткий фидбек → следующий шаг
- Не нужны объяснения — просто сделать и показать результат
- Предпочитает видеть изменение сразу, а не получать вопросы
