# Документирование изменений — CS Platform

## Структура документации

```
docs/
├── ARCHITECTURE.md            # Живая карта проекта — модули, границы, потоки (ГЛАВНЫЙ)
├── DECISIONS.md               # Журнал архитектурных решений (ADR)
├── UI_DESIGN_SYSTEM.md        # Система дизайна
├── TELEGRAM_BOT.md            # Документация Telegram/Teams бота
├── BUSINESS_REQUIREMENTS.md   # Бизнес-требования
├── USER_GUIDE.md              # Гайд для конечных пользователей
└── database/
    └── SCHEMA.md              # Схема БД (таблицы, views, RPC)
```

## Какой документ обновлять

| Тип изменений | Документ(ы) |
|---------------|-------------|
| Новый модуль, новый слой архитектуры | `docs/ARCHITECTURE.md` |
| Архитектурное решение (выбор подхода) | `docs/DECISIONS.md` (новая запись ADR) |
| Новая таблица, view, RPC функция | `docs/database/SCHEMA.md` |
| Telegram/Teams бот — новый инструмент | `docs/TELEGRAM_BOT.md` |
| UI — компоненты, токены, паттерны | `docs/UI_DESIGN_SYSTEM.md` |
| Бизнес-логика, правила расчётов | `docs/BUSINESS_REQUIREMENTS.md` |
| Инструкции для пользователей | `docs/USER_GUIDE.md` + `src/components/dashboard/help/HelpContent.tsx` |
| Что нового (changelog для пользователей) | `MANUAL_BUILD_CHANGELOG_ITEMS` в `ActivityContent.tsx` |

## Обязательные синхронизации (из CLAUDE.md)

```
USER_GUIDE.md изменился  →  синхронизировать HelpContent.tsx
Любое изменение видимое пользователю  →  добавить в MANUAL_BUILD_CHANGELOG_ITEMS
```

`MANUAL_BUILD_CHANGELOG_ITEMS` — в `src/components/dashboard/activity/ActivityContent.tsx`:
- Новые записи в **начало** массива
- Типы: `Добавлено` | `Обновлено` | `Исправлено`
- Формат даты: `ДД.ММ` (например `03.03`)
- Максимум 12 записей — при добавлении удалять старые с конца

## Формат ADR (DECISIONS.md)

```markdown
## [N] Название решения (YYYY-MM-DD)

**Контекст:** Почему нужно было принять решение.

**Решение:** Что выбрали.

**Причина:** Почему именно это.

**Последствия:** Что меняется, плюсы/минусы.
```

## Процесс

1. Определить тип изменений → выбрать документ по таблице
2. Прочитать текущее содержимое документа (контекст)
3. Добавить/обновить секцию (НЕ переписывать весь документ)
4. Если изменение видимо пользователю → обновить ActivityContent.tsx
5. Показать пользователю список обновлённых файлов
6. Предложить коммит: `docs: <краткое описание>`

## Чеклист

- [ ] Выбран правильный документ
- [ ] Прочитано текущее содержимое

- [ ] Если USER_GUIDE.md изменён → синхронизирован HelpContent.tsx
- [ ] Если изменение видимо пользователю → добавлен MANUAL_BUILD_CHANGELOG_ITEMS
